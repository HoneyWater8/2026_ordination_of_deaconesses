**2026-10-24 사용자가 작업 중인 초대장 링크를 담당 전도사(발주)에게 처음 공유했습니다.** 이때부터 `main` 푸시는 곧바로 발주자가 보는 화면을 바꿉니다.

사용자가 그 자리에서 남은 과제로 알린 것: ① 예배 순서 ② 집사님들(임직자) 이미지 ③ 각 페이지 「?」 설명글 검토. 담당 전도사의 답:

| 항목 | 답 | 상태 |
|---|---|---|
| 예배 순서 | "예배순서는 뺍시다 너무 많아서" | ✅ 섹션 제외 (2026-10-24) |
| 「?」 설명글 | "3.은 성경구절을 말하는건가?" — 무엇을 검토하는지 되물음 | ⏳ 「?」에는 꽃 이름·장절·구절·**해설글**이 나온다. 8개를 카톡용으로 정리해 주겠다고 제안해 둠 |
| 임직자 사진 | — | ⏳ 임직 예정자 카톡방에서 수령 예정 ([[asset-pipeline]]) |

**Why:** 발주자와의 대화는 레포 밖(카카오톡)에서 오가고, 사용자가 일부만 붙여 넣어 전달합니다. 무엇을 이미 보여 줬고 무엇을 기다리는지 기록이 없으면 다음 세션이 이어 가지 못합니다.

**How to apply:**

- 사용자가 카톡 대화를 붙여 넣으면 **원본은 `docs/담당자 대화 원본.txt`(git 제외)에, 익명화본은 `docs/chat-transcript.txt`에 이어 적습니다.** 원본의 실명은 `[개발자]` · `[담당 전도사]`로 바꾸고, 「○○형제」처럼 호칭 안에 든 이름도 `[개발자] 형제`로 바꿉니다. 커밋 전에 추가한 줄에 실명이 없는지 검사합니다. 결정 사항은 `docs/requirements.md`에도 반영합니다.
- 원문에 날짜가 없으므로 익명화본에는 「사용자 전달 날짜」만 적고 대화 날짜를 지어내지 않습니다.
- 발주자에게 보이는 변경이므로, 큰 화면 변경은 푸시 전에 사용자가 로컬에서 확인할 수 있게 합니다 (2026-10-24 예배 순서 제외 때 사용자가 로컬 서버로 확인한 뒤 푸시를 지시).
- 「?」 해설글 피드백이 오면 `FE/src/data/ordination.ts`의 `flowers.info`만 고칩니다. 새 글자가 생기면 부분 폰트를 다시 만듭니다.
