졸업 레포와 같은 두 축입니다 — 가족 한마당에서 페이지뷰·UV를 아예 수집하지 못한 것이 아쉬웠던 지점이라 졸업부터 사전에 붙였습니다.

| | Vercel Web Analytics | Google Analytics 4 |
|---|---|---|
| 상태 (2026-10-23) | ✅ CLI로 활성화. `<Analytics />` 연결 | ✅ 2026-10-25 사용자가 `G-YBDXKFTNVQ` 전달 → `index.html` 표준 스니펫. 졸업(`G-P7PXPF9CWM`)과 다른 ID |
| 보존 | **1개월** (Hobby) | 14개월 |

**Why 둘 다인가:** Hobby는 커스텀 이벤트를 지원하지 않아 "어디까지 봤나 / 지도 앱·사진 확대를 눌렀나"는 GA4가 맡습니다. 코드의 `track()` 호출은 미리 넣어 두었고, 스니펫을 넣어 수집이 시작됐습니다.

**How to apply:**

- GA4는 `FE/index.html`의 **구글 표준 스니펫 그대로** 둡니다 (`?ga_debug=1` 디버그 분기 포함 — 졸업 `index.html` 참고). 모듈로 감싸 동적 로드하지 않습니다 — 졸업 레포에서 `page_view`가 `en` 없이 나가 GA가 버렸습니다(2026-09-11).
- 전송 확인은 Network의 `collect?v=2` **payload의 `en`**까지 봅니다. `204`는 처리 성공이 아닙니다 (졸업 레포에서 오판한 지점).
- 로컬에서 확인할 때는 Playwright로 `collect` 요청을 **가로채 내용만 읽고 보내지 않습니다** — 그대로 보내면 127.0.0.1 방문이 실데이터에 섞입니다. 2026-10-25 이 방법으로 `page_view`·`section_view`·`photo_open`(`photo`)·`exception`·사용자 속성 `in_app`(카카오톡·네이버 등 UA별)을 확인했습니다.
- ⏳ **GA4 맞춤 측정기준 등록은 사용자가 GA 화면에서 직접 합니다** (2026-10-25 등록 방법 안내, 목록은 README 「사용자 집계」). 등록 전 데이터에는 소급되지 않습니다 — 졸업 레포는 행사가 끝난 2026-10-25에야 등록해 행사 기간을 섹션별로 볼 수 없었습니다. 등록했는지 확인되면 이 줄을 고칩니다.
- 2026-10-25 졸업 레포 운영 통계에서 아쉬웠던 두 가지(카카오톡 유입이 Direct로 잡힘 · 측정기준 늦은 등록)를 반영해 `in_app` 사용자 속성과 `exception`(실기기 오류) · `photo_open`의 `photo`를 추가했습니다.
- ⏰ 예배가 2026-11-08이라 Vercel 데이터는 **2026년 12월 초 전에** 대시보드를 캡처해야 남습니다.
