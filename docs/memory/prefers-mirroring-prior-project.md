구조·스택·작업 방식을 정할 때 **앞선 프로젝트를 그대로 답습하는 쪽**을 선택합니다. 세 프로젝트 연속으로 확인되었습니다.

- 졸업(2026-09-07): "참고 레포를 참고하여 폴더 구조를", "스택은 참고 레포와 동일하도록"
- 이 프로젝트(2026-10-23): "두 레포의 작업 방식과 기록, 기술 스택, 폴더 구조 등 여러 컨벤션을 그대로 진행하고 싶어", "지도는 하나로가족한마당 때 구현한 기록이 있을거고, 사진·동영상은 졸업장 때 구현한 기록이 있을거야"
- 화면 동작도 마찬가지(2026-10-25): "scroll 표시되는건 참고 레포 처럼 첫 진입 후 사용자 동작이 없을때 몇 초 뒤 표시되도록" → 졸업 `ScrollHint`·`useScrolled`를 그대로 가져옴. 「참고 레포」는 별말 없으면 졸업 레포

**Why:** 같은 사람이 연달아 만드는 소규모 프로젝트라, 구조가 같으면 다음 프로젝트에서도 바로 읽힙니다. 최신 스택으로 갈아타는 이득보다 일관성의 이득이 큽니다.

**How to apply:**

- 구조·설정·네이밍에 선택지가 생기면 먼저 [[reference-prior-repos]]에서 같은 상황을 어떻게 처리했는지 찾아 그대로 따릅니다.
- 참고 레포에 없는 새 패턴이 필요하면 이유를 밝히고 제안한 뒤 진행합니다.
- **작업 순서**: 착수 시 "빠짐없이 정확하게 파악" → 결정이 필요한 것만 질문 → 답을 받은 뒤 실행. 큰 작업 전에는 "작업 범위 정확하게 파악/더블체크하고 진행해"라는 지시가 반복됐습니다. 문서만이 아니라 실제 지시 기록·커밋 데이터로 대조할 것.
