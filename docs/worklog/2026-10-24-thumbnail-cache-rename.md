# 2026-10-24 · 카카오 썸네일 캐시 — 파일명 변경으로 교체

> 썸네일을 같은 경로로 교체했더니 카카오 공유 디버거에서 캐시 초기화를 여러 번 눌러도 옛 이미지가 나왔다. 서버는 새 파일을 내보내고 있었으므로 카카오 쪽 이미지 보관 문제로 보고, 파일명을 바꿔 `og:image`를 새 주소로 돌렸다.

## 한 일

- `FE/public/icons/thumbnail.png` → `thumbnail-v2.png` (`git mv`, 내용 동일)
- `FE/index.html` — `og:image` · `twitter:image`를 새 주소로
- README · `scripts/thumbnail.html` 주석 · 메모리(자산 파이프라인 · 카카오 앱 설정)

## 판단한 것

**1. 원인은 우리 서버가 아니다**

쿼리 없는 실제 주소를 일반 요청과 카카오 스크래퍼 User-Agent로 각각 받아 보니 둘 다 새 파일(로컬과 SHA-256 동일)이었습니다. Vercel 응답도 새 배포의 것이었습니다(`X-Vercel-Cache: HIT`, `Last-Modified` 새 배포 시각). 그러니 옛 이미지는 카카오가 이미지 주소 단위로 보관한 사본입니다. 공유 디버거의 초기화는 페이지 OG 정보를 다시 읽게 할 뿐, 주소가 같은 이미지는 다시 받지 않는 것으로 보입니다. 우리가 `/icons/`에 붙인 1시간 캐시 헤더(`max-age=3600`)도 그 보관을 허용합니다.

**2. 주소를 바꾸는 것이 확실한 방법**

졸업 레포 README에도 "확실히 하려면 파일명을 바꾸고 og:image도 함께 고치라"고 적혀 있었습니다. 앞선 작업로그(`2026-10-24-thumbnail-larger-type.md`)에서 "졸업에서 같은 경로 교체가 괜찮았으니 파일명을 유지한다"고 판단한 것은 틀렸습니다 — 그때는 우연히 문제가 없었던 것으로 봅니다. 메모리에 「썸네일을 바꿀 때마다 파일명을 새로」로 정정했습니다.

**3. 옛 파일은 지움**

이미 보낸 카카오톡 카드는 카카오가 보관한 사본을 쓰므로 우리 쪽 옛 주소가 필요 없습니다. 같은 이미지가 두 이름으로 남지 않게 옛 파일을 지웠습니다.
