> 사용자가 측정 ID `G-YBDXKFTNVQ`를 전달해 `index.html`에 구글 표준 스니펫을 넣었다. 이어서 「쓸만한 통계 이벤트를 더 추가할 수 있는지 검토」 요청에, 졸업 레포 운영 통계에서 아쉬웠던 점을 근거로 네 가지를 제안했고 사용자가 모두 진행하라고 했다.

## 판단한 것

**1. 무엇을 더할지 — 졸업 레포 운영 통계가 근거**

졸업 레포 README 「운영 통계」에서 ① 카카오톡 앱 안 브라우저가 출처를 넘기지 않아 유입이 95% Direct로 잡혀 카카오톡과 다른 경로를 나눌 수 없었고, ② `section`·`video`를 행사가 끝난 뒤 맞춤 측정기준으로 등록해 행사 기간을 섹션별로 볼 수 없었습니다. 그래서 ① 사용자 속성 `in_app`, ② 지금 등록할 측정기준 목록을 우선했습니다. 여기에 아직 실기기로 확인하지 못한 아이폰·카카오톡 앱 안에서의 실패를 보려고 `exception`을, 가벼운 선택지로 `photo`를 더했습니다.

**2. 넣지 않은 것**

로고(교회 홈페이지)·지도 앱 링크 클릭은 GA 향상된 측정의 「외부 링크 클릭」이 이미 셉니다. 확대 보기 안에서 넘긴 횟수 · 지도 드래그·확대는 수만 늘고 판단에 쓸 데가 없어 제안하지 않았습니다.

**3. `in_app`은 `index.html`에서, `config`보다 먼저**

모듈에서 나중에 set 하면 첫 `page_view`에는 붙지 않습니다. CLAUDE.md의 「GA 초기화는 표준 스니펫 그대로」는 모듈로 감싸 동적 로드하지 말라는 뜻이라, 같은 인라인 스크립트 안에서 표준 `gtag('set', 'user_properties', …)`를 한 줄 더하는 것은 그 규칙 안입니다. 구분은 UA 문자열로 합니다 — 카카오톡은 안드로이드·iOS 모두 `KAKAOTALK`, 그 밖의 안드로이드 앱 안 브라우저는 `; wv)`로 `other_webview`. iOS의 다른 앱 안 브라우저는 UA로 구분되지 않아 `browser`로 잡힐 수 있습니다.

**4. 오류는 우리 앱 것만, 적게**

다른 출처 스크립트(GA·카카오·YouTube)의 오류는 브라우저가 가려 `Script error.`만 오고, 앱 안 브라우저가 끼워 넣은 스크립트의 오류는 파일 이름이 없어 둘 다 버립니다. 같은 오류가 반복·연쇄돼도 넘치지 않게 같은 내용 1회 · 최대 5건으로 묶었습니다. `fatal`은 앱 코드에서 처리하지 못한 오류만 true입니다.

**5. 맞춤 측정기준 등록은 사용자 몫**

GA 관리 화면에서 해야 하고(API 권한 없음) 측정 ID 주인의 계정이라 사용자에게 목록과 순서를 드렸습니다. `share_copy`의 `ok` · `exception`의 `fatal`은 졸업처럼 등록하지 않습니다.
