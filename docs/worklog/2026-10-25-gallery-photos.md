# 2026-10-25 · 갤러리 사진 8장 — 칸을 사진 비율대로

> 사용자가 갤러리 원본 8장을 `01~08`로 번호를 붙여 저장하고 「이미지에 맞게 칸의 비율이나 배치를 적절하게」 해 달라고 했다. 모두 가로 사진이라 시안의 정사각 칸을 버리고, 같은 줄은 높이를 맞추고 폭은 사진 비율대로 나누는 배치로 바꿨다.

## 한 일

- `resize-photos.py --source assets/photo-originals/gallery --slug gallery` → `FE/public/gallery/{thumb,full}/01~08.webp` (29.1MB → 1.7MB)
- 데이터 — `slots`(칸 수)를 없애고 `rows: [1, 2, 1, 1, 2, 1]`(줄마다 사진 수), 사진마다 `ratio`(원본 가로/세로)
- `Gallery.tsx` — 2열 grid(넓게 · 2 · 2 · 넓게 · 2, 정사각/16:10) → 줄마다 flex. 칸에 `flex: <비율> 1 0` + `aspectRatio: <비율>`. 사진이 없는 칸의 번호 자리 삭제
- `resize-photos.py` — 갤러리 변환 때 사진마다 비율을 출력(데이터에 옮겨 적을 값), 도움말 갱신
- README · 요구사항 · 메모리. README 디자인 토큰의 교차 배경 설명이 예배 순서 제외(10-24) 전 그대로여서 함께 고침

## 판단한 것

**1. 같은 줄 높이 맞춤 · 폭은 비율대로 (자르지 않음)**

받은 사진의 비율은 3:2가 5장, 16:9 1장, 1.97:1 1장, 2.63:1 1장으로 모두 가로입니다. 시안의 정사각 칸에 넣으면 3:2는 폭의 1/3, 2.63:1 파노라마는 62%가 잘립니다. 고려한 안:

| 안 | 장단 |
|---|---|
| 한 줄에 한 장씩, 사진 비율 그대로 | 잘리지 않지만 390 화면에서 약 1,700px — 화면 두 장 |
| 2열 칸을 3:2로 통일 | 3:2는 맞지만 파노라마 · 16:9가 잘림 |
| **같은 줄 높이 맞춤 · 폭은 비율대로** | 잘리지 않고 약 1,030px(기존 시안 배치와 비슷) |

세 번째를 골랐습니다. 사진 갤러리에서 흔한 배치(justified)입니다. 같은 줄의 칸에 flex-grow를 비율로 주고 기준 폭을 0으로 두면, 폭은 비율대로 나뉘고 높이는 (줄 폭 − 간격) ÷ 비율 합으로 같아집니다. 비율은 데이터에 미리 적어서, 사진이 로드되기 전에도 칸 크기가 정해져 배치가 흔들리지 않게 했습니다.

**2. 줄 구성 — 사용자가 붙인 번호 순서를 그대로**

사용자가 번호를 붙여 줬으므로 순서는 바꾸지 않고 줄만 나눴습니다.

| 줄 | 사진 | 이유 |
|---|---|---|
| 1 | 01 교회 외관 | 첫 사진을 크게 — 시안도 첫 칸이 넓은 칸 |
| 2 | 02 외관(항공) + 03 설교 | 3:2와 16:9는 비율이 비슷해 폭이 46:54로 크게 어긋나지 않음 |
| 3 | 04 본당 예배 (1.97:1) | 파노라마는 두 장이 한 줄이면 높이가 너무 낮아짐 |
| 4 | 05 본당 전경 (2.63:1) | 〃 |
| 5 | 06 기도 + 07 야외 찬양 | 둘 다 3:2라 반반 |
| 6 | 08 운동장 행사 | 마지막을 크게 |

03을 한 줄에 두고 01 + 02를 짝지으면 한 줄 사진이 03 · 04 · 05로 세 줄 연속이 되어 위 안을 택했습니다. 04 · 05 두 파노라마가 이어지지만 비율이 달라 높이가 다릅니다(390 화면에서 176px · 132px). 확대 보기 순서도 번호 순서와 같습니다.

**3. 번호 자리(placeholder)는 없앰**

사진이 다 왔고, 배치를 비율로 정하면 사진이 없는 칸의 크기를 정할 기준이 없습니다. `rows` 합보다 사진이 많으면 남는 사진은 한 장씩 한 줄로 붙입니다 — 데이터를 덜 고쳐도 사진이 사라지지 않게.
